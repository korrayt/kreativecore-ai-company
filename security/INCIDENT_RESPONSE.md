# Incident Response

## Severity

- `SEV-1`: Active compromise, leaked production secret, or major data exposure
- `SEV-2`: High-risk vulnerability without confirmed exploitation
- `SEV-3`: Limited issue with workaround
- `SEV-4`: Low-risk hardening task

## Response

1. Contain
2. Revoke / isolate
3. Preserve evidence privately
4. Assess scope
5. Fix
6. Verify
7. Communicate appropriately
8. Record lessons and prevention

Never place sensitive incident evidence in a public GitHub issue.
